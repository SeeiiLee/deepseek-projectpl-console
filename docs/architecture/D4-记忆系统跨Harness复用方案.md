# D4 记忆系统跨 Harness 复用方案（Codex / Zcode / Kimi Work / workbuddy）

> 状态：可行性设计稿，待 Cyrus 拍板。不写代码。
> 背景：Cyrus 同时在用多个 Harness 类应用（DSH、Codex、Zcode、Kimi Work、workbuddy），问记忆系统能否复用、要做什么适配。日期：2026-08-20

## 0. 结论先行

1. **能复用，但形式不是「把 DSH 插件搬过去」，而是「核心/外壳分离 + 分层适配」**。实测结论：记忆系统与 DSH 的耦合面很薄（一层 seam 适配代码），核心资产（加密存储、向量嵌入、检索内核、提取管线、评测体系）全部是宿主无关的。这是这套系统最值得保护的架构属性。
2. **MCP 适配器是杠杆最大的一笔投资**：Codex、Zcode、Kimi Work 全都支持 MCP（本文附核实证据），做一个「记忆 MCP 服务器」适配器，一端投入、三端通吃，还能覆盖未来任何支持 MCP 的新宿主。
3. **各端能力有真实差异，召回质量会分档**：DSH 原生注入（systemPrompt.section 常驻）是最强形态；MCP 形态下召回变成「工具调用」，时机靠模型自觉，质量必须在各端重新评测，不能拿 DSH 的 R 层结论直接外推。
4. **建议顺序**：先收尾 DSH 侧 P5/P6（拆分期不并行大改）→ 核心/外壳拆分 → MCP 适配器 → 逐端接入。workbuddy 的扩展面我未核实，附验证清单。

## 1. 实测：记忆系统与 DSH 的耦合面有多薄

2026-08-20 对 plugins/memory 源码的实测，耦合面（要重写的）与核心（直接带走的）划分如下：

| | 内容 | 跨端命运 |
|---|---|---|
| **耦合面（薄）** | systemPrompt.section 注入（order 150）、webServer.register 路由、ctx.credentials 凭据、ctx.tools 工具注册、personal-shell UI 槽位 | 每端重写一次适配器，估计每端数百行 |
| **插件间依赖（中）** | project-control（身份 Host API）、connection-center（提取连接）、skill-library（M2 技能提升） | 其他端没有等价物，需降级方案（见 §3 各端表） |
| **核心（厚，全带走）** | SQLCipher 加密 SQLite 存储、bge-m3-onnx 嵌入（560M 模型资产）、检索内核（hybrid 召回）、提取 runtime（DeepSeek API）、迁移链、评测 harness | 宿主无关，原样复用 |
| **数据根模式** | F 盘数据根、DPAPI 加密（插件侧 PowerShell）、main.js 仅 6 个 env 注入 | 模式可平移到任何桌面端 |

判断依据：v0.3.0 的 P0–P4+P6-1 全部跑在官方 seam 上、无一处私改上游——这同时意味着**没有一处依赖 DSH 私有实现**，移植没有隐藏地雷。

## 2. 适配分层

```
┌─────────────────────────────────────────────┐
│ 记忆核心（存储/嵌入/检索/提取/评测）——宿主无关 │
└─────────────────────────────────────────────┘
        ▲ 定义一个 Host 适配接口（端口）
   ┌────┴─────┬──────────┬───────────┐
   T0 DSH 原生  T1 MCP 适配器  T2 提示词兜底
   （现状）     （主投资方向）   （弱形态保底）
```

- **T0 DSH 原生**（现状）：systemPrompt.section 常驻注入 + 全量插件间集成。能力上限。
- **T1 MCP 适配器**：把记忆核心包成一个 MCP 服务器（stdio 本地进程），暴露 `memory_recall`（检索注入）、`memory_store`（写入）、`memory_status` 等工具。任何支持 MCP 的宿主配置一行即可接入。模型资产与数据库走共享数据根。
- **T2 提示词兜底**：对无 MCP 的宿主，退化为「AGENTS.md + CLI」——宿主启动时读一份由记忆系统导出的上下文摘要文件。弱形态（无实时召回），但保证任何端都不至于零记忆。

**关于「召回质量分档」的如实说明**：T0 形态下召回内容常驻 systemPrompt，模型必然看见；T1 形态下记忆是工具，模型「想起来要查才查」——行业通病，缓解手段是在各端的系统指令/AGENTS 里写清「何时应查记忆」的引导规则（这正是 T2 经验可以直接复用的地方）。各端接入后必须重跑评测门，R 层结论按端出报告，不混用。

## 4. 跨端共享：一份记忆库，还是各端一份？

**建议：单一数据根，全端共享一份库。** 理由：你在 DSH 里聊过的项目上下文，在 Codex 里写代码时应该能被想起——这正是跨端复用的核心价值；各端各一份等于把记忆切成孤岛。

三个必须解决的工程点（都不涉及选型，只列纪律）：

1. **单写入者**：同一时刻只允许一个端持有写锁（DSH 现有 writer-lock 模式推广），其余端只读或排队——多端并发写 SQLCipher 库是毁库最快的方式。
2. **来源标记**：每条记忆记录来源端（dsh/codex/zcode/...），检索时可按端过滤，出问题可溯源。
3. **模型资产共享**：bge-m3 等模型放共享数据根的 models/ 目录，各端适配器引用同一份，不重复占盘（单模型 560M，多端各存一份是浪费）。

## 5. 代价、前提与风险

**代价**：核心/外壳拆分是一次 Class A 重构（要把当前插件里 seam 调用与核心逻辑显式分层，定义 Host 适配接口）；MCP 适配器是新工程（含评测）。量级估计：拆分 > MCP 适配器 > 单端接入调试。

**前提**（两个，都是已确立纪律的延伸）：

1. DSH 侧 P5/P6 先收尾——拆分期间不并行架构大改，否则拆分目标在移动。
2. 商用剥离清单（PUBLISHING_RULES 已有）的许可核查扩展到 MCP 形态——分发形态变了，SQLCipher/模型权重条款要按新形态再过一遍。

**风险**：

- **质量外推风险**（最大）：DSH 的 R 层达标结论不能外推到 MCP 端，各端独立评测，宣发时按端标注能力等级。
- **身份体系降级**：DSH 靠 project-control 提供项目身份，其他端没有——记忆里「这是哪个项目的上下文」在非 DSH 端会退化，需要在适配器里用工作区路径等弱标识替代。
- **维护面扩大**：每多一端，上游 seam 观察（D2 §3.5）就多一个观察对象；Zcode/Codex 自身的版本演进也可能破坏适配器。

### 8.3 判断：定位成立，但不是空地——必须踩三块差异化楔形

「野蛮生长阶段」的判断与证据一致（无定型架构、benchmark 各自为战、集成碎片化）；但「跨端 coding 记忆」**已有资金充足的执行者**——MemoraX Code 的四端路线与本文 §6 几乎同构。结论：可做，但差异化必须踩在别人踩不了的位置上：

1. **本地优先 + 零守护进程 + 加密**。我们：SQLCipher 加密 SQLite 单文件 + 本地 bge-m3 嵌入 + DPAPI，开箱即用。对比：Hindsight 要跑 PostgreSQL 守护进程，MemoraX 的长期记忆在云平台上。开发者记忆含代码与业务上下文——**「记忆是一个你拥有的加密文件，不是一个服务」**是独占叙事。
2. **个人单用户纵深，不做企业多租户**。Mem0 卷企业合规、MemoraX 卷模型训练；单开发者、多端、零运维这个位置反而空着。
3. **记忆 → 工程制品的蒸馏**。我们的 M2 机制（记忆蒸馏提升为 skill / AGENTS.md 片段）把经验式记忆转成工程制品——AGENTS.md 是宣言式记忆（人写的宪法），本系统是经验式记忆（机器攒的战壕笔记），且能把后者蒸馏进前者。竞品未见此机制（Hindsight 的 Mental Models 接近，但产出的是知识页而非工程制品）。

另记 Cyrus 的一手资产：他本人就是目标用户的 extreme case——DEVLOG、经验.md、NEXT.md 关键坑清单，这套手工经验沉淀文化就是产品需求的一手来源，funded 竞品没有这种贴身工作流。

### 8.4 对 §6 路线的三条修正

1. **不打 benchmark 战争**（资源不对等）。评测门只服务自家发布质量；但必须覆盖「想得对、出现得刚刚好」类精度指标——MemoraX 的 85.5% 触发一致率已经定义了用户对「记忆不自作聪明」的预期基线。
2. **DSH 端必须靠深度集成拉开差距**（2026-08-20 Cyrus 修正：project-control 身份、skill-library 蒸馏、connection-center 提取是**防御纵深与体验壁垒**，不是核心壁垒；核心壁垒是召回管线的工程设计，见 §9）。社区已有浅层 recall 插件（dsh-hindsight-memory），浅层召回插件没有存在理由；集成的角色是让漏斗设计在 DSH 端发挥到上限。
3. **核心/外壳拆分（§6 第 2 步）优先级上升**。MemoraX Code 已四端在跑，跨端窗口以月计——拆分 ADR 应在 P5/P6 收尾期同步起草，而非收尾之后才启动。

## 9. 核心壁垒修正：漏斗式召回管线设计（2026-08-20 Cyrus 拍板，认知科学四条证据线同日核实）

### 9.1 Cyrus 的论点（形式化）

语义相似不是召回的唯一标准。有用的召回是一条逐级收窄的工程管线：

```
模糊线索（气味 / 图片 / 触感 / 情境碎片 / 灵光一闪）
 → ① 类型判断（这是什么类型的题）
 → ② 候选枚举（这个类型有且仅有哪几种解法——解空间地图）
 → ③ 判别探测（章鱼还是鱿鱼？去摸尖头还是圆头——最小判别特征）
 → ④ 蓝图执行（选定最短 / 最有把握的路径，按解法蓝图求解）
 → ⑤ 结果回写（解法是否奏效，更新记忆的标记与特征）
```

配套的「记忆系统设计七问」（Cyrus 原话）：哪些该记 / 怎么记 / 怎么储存 / 怎么召回 / 召回什么 / 召回如何筛选 / 最终如何呈现。任何记忆系统（含全部竞品）都隐式回答了这七问——竞争力是这七个答案的质量，不是训练投入、合规性或榜单名次。

### 9.2 认知科学证据（2026-08-20 核实，四线全部命中）

| Cyrus 的主张 | 文献证据 | 核实来源 |
|---|---|---|
| 先判类型、再找解法（考试例） | Chi, Feltovich & Glaser（1981, Cognitive Science 5:121-152）：物理专家按深层解题原理（如能量守恒）给题目分类，新手按表面特征（斜面、滑轮）分类；问题图式「大幅减少找到解法所需的搜索量」；专家把更多时间花在**决定问题如何表征**上，而非急着找解法 | UPenn Citation Classic、UCLA 认知心理学教材（S/A 级） |
| 语义并非召回唯一标准；记忆要有标记/特征才好召回 | Tulving 编码特异性原则（Tulving & Thomson 1973）：线索只有参与过原始编码才有效；**线索依赖遗忘 = 记忆仍在库里但取不出（available ≠ accessible）**；Godden & Baddeley 潜水员实验（编码/提取情境匹配，回忆率差约 40%）；Mäntylä（1986）：自生成线索下 600 词回忆率超 90%；Nairne（2002）修正：线索必须有**诊断性**——能区分目标与非目标，而不只是「存在」 | Purdue 记忆研究手册、《心理学名词》第二版（S/A/B 级） |
| 人脑有记忆盲区，Harness 不应照抄 | Richards & Frankland（2017, Neuron 94:1071）；Ryan & Frankland（2022, Nat Rev Neurosci 23:173）：相当部分遗忘是**记忆印迹细胞从可激活态切换到不可激活态的适应性机制**，速率受环境调节——「盲区」部分是功能而非缺陷；工程含义不是「永不遗忘」，而是**受控可及性 + 显式留存标记**（这恰好强化七问之首「哪些该记」） | 清华生命学院钟毅团队 2026 研究及其参考文献链（S/A 级） |
| 漏斗式逐级收窄（章鱼例） | MAC/FAC 模型（Forbus, Gentner et al. 1994）：人类类比检索的主流计算模型**本身就是漏斗**——廉价特征向量先从大库粗筛约 3 个候选，再由结构映射引擎（SME）精排；Gentner, Rattermann & Forbus（1993, Cognitive Psychology 25:524-575）：**表面相似性决定「能否想起」，结构相似性决定「想起来的有没有用」** | Northwestern QRG 系列论文、《心理学报》2018 综述（S/A 级） |

### 9.3 超出原论点的一个推衍（Kimi 补充）

Gentner 1993 的「可检索性 vs 推理有效性」分离，恰好解释了「灵光一闪的回忆大部分没用」：自发召回由表面相似驱动（所以多数无用），有用召回必须由结构特征驱动。人脑漏斗的已知弱点是**表面偏差**——所以 Harness 记忆的机会不是模仿人脑漏斗，而是**修正它**：编码时强制打上类型/结构特征标记（七问之二「怎么记」），让结构层成为检索入口，语义层退为末级精排。这是「机器记忆可以超过人脑记忆」的具体位置。

### 9.4 对竞争格局的修正

- Hindsight / Mem0 / Zep 的召回本质是「语义相似 + 图扩散 + 重排」——只有漏斗的末两级（粗筛 + 精排），缺类型判断、候选枚举、判别探测三级。
- MemoraX 的 RL 路线是让模型自己学召回策略（学习式）；漏斗是工程式。工程式的优势：可解释、可调试、可直接进我们的 R 层评测门；学习式上限更高但黑盒。两路线胜负未分，但工程式与「个人基础设施」定位（本地、可控、可审计）天然契合。
- **诚实标注**：这条壁垒是设计领先，不是资源/专利壁垒——设计可被抄袭。保鲜依赖三样：① 评测门沉淀的可重复实证数据；② 迭代速度；③ 蒸馏产物（Task Pack / 技能）随使用积累的复利。

### 9.5 与自家架构的对照：漏斗在 P5 里已经萌芽

| 漏斗级 | P5/手册现有构件 | 差距 |
|---|---|---|
| ① 类型判断 | Catalog（类型索引） | 类型层尚未成为检索的一等入口，仍混在 hybrid 语义召回里 |
| ② 候选枚举 + 蓝图 | Task Pack（任务级注入） | 需要显式的「解空间地图」schema（该类型有几种解法、各自路径） |
| ③ 判别探测 | **无** | 完全空白——主动追问最小判别特征（章鱼/鱿鱼式）建议登记为 P7 候选：主动判别式召回 |
| ④ 蓝图执行 | Task Pack + skill-library | 已有雏形 |
| ⑤ 结果回写 | Daydream（离线反思巩固） | 需把「是否奏效」显式回写到记忆的特征标记上 |
| 编码侧埋点 | 提取管线 | 提取 schema 从「记内容」扩展到「记类型/特征/解空间位置」（P5 后续迭代可承载，走 V2 插件通道） |

结论：Cyrus 的漏斗理论与 P5 架构升级（Catalog/Task Pack）方向一致——这条思考线已经在架构里生长；判别探测是把漏斗补全的最后一块空白。

### 9.6 MemoraX Code 产品侧实测（2026-08-20 读官方仓库 README，补 Cyrus 判断的核实证据）

Cyrus 判断「MemoraX 的 RL 路线是融资噱头，产品里的学习只是召回 Agent 调策略」。核实结果——**产品侧判断成立，但 RL 线应定性为「未兑现的期权」而非噱头**：

**实测到的产品架构**（github.com/memorax-ai/memorax-code，MIT，npm 全局安装）：

- 四层记忆边界：**Coding Memory**（修复经验/失败方案/设计理由/坑）、**Repo Memory**（架构图/模块归属/入口/commit 证据）、**Personal Memory**（协作偏好）、**Procedure Memory**（可复用步骤/检查清单/验证门禁——与我们的 Task Pack/解法蓝图高度同构）。
- 后台自动回写 + 写入前语义去重（等价不写、精化则更新并删除被取代表述、显式遗忘只删指定条目）。
- **云依赖**：长期记忆需 MemoraX 云端 API key；检索/回写内容会上云（官方明示边界）。本地只有活动计数与 Viewer。
- 分发极轻：`npm install -g` 一行命令，自动检测并接入 Codex / Claude Code / **DSH** / OpenCode 四端。
- **产品里没有任何 RL 的影子**——RL「内生记忆」叙事只存在于母公司论文与融资稿（LoCoMo-Refined SOTA、ScriptMem、SWE-context-bench）。

**三点结论**：

1. Cyrus 的产品侧判断成立：这是一个工程化记忆层，不是学习式系统；其工程完成度和我们同代。
2. 但 RL 线不是纯噱头：郝建业团队（南大 RL 实验室、ICML 2026 十篇）有真实训练能力，且公开写明意图是「把记忆判断变成可通过训练持续提升的能力」，并在建评测基准制造奖励信号。**今天的工程化产品 = 明天训练的数据采集器**——这个逻辑对我们同样成立：我们的 R 层评测门 + 漏斗决策点日志就是自己的数据工厂，这是路线无关的护城河，应写进 ADR。
3. 漏斗深度对比：他们的四层边界 ≈ 静态类型层（半只脚进了漏斗①），Procedure Memory ≈ ② 的雏形；**动态判题、解空间枚举（「有且仅有 3 种解法」）、判别探测（③）、结果回写特征（⑤）在其公开材料中完全看不到**——注意「看不到」不等于「没有」，标注为不可验证项。我们的深度优势仍在，且云依赖 vs 本地加密的定位分野没有变化。

### 9.7 MemoraX 技术路线深读（2026-08-20：郝建业专访 + 同赛道学术论文群；回答「他们比我们先进在哪」）

**一手来源**：未找到单一「MemoraX 论文」。最完整的技术阐述 = 郝建业专访（斗象科技/FreeBuf，2026-05-07）；辅助 = 2025-2026 同赛道 RL 记忆论文群（MemRL arXiv:2601.03192、AgeMem arXiv:2601.01885、Mem-α、Memory-R1、MemSkill 等，S/A 级）。

**郝建业的核心论证（专访原话要点）**：

- 「记忆本质上是一个**序列决策问题**：什么该记、什么该忘、什么时候调取什么信息——这天然是强化学习的领地。」
- 「没有办法靠人工专家打造『怎么记住前面 3 万字对话』的专属训练语料，只能设定系统优化目标，用强化学习**反向迭代优化记忆模型参数**。」
- 技术体系三支柱：可学习记忆策略引擎、记忆基模、自演进 Agent Harness。宣称 LoCoMo-Refined 领先第二名 30%、训练效率提升 400 倍、Token 消耗降低 30%（均为公司披露口径，未见可复现 artifact）。

**同赛道学术群的关键机制**（帮助理解 RL 线到底在做什么）：MemRL 把记忆组织为 意图-经验-效用 三元组，对每条记忆的效用做 Bellman 更新（Q 值），召回按学到的效用排序；AgeMem 把 存/取/改/摘要/丢弃 定义为 Agent 的动作，用三段式渐进 RL + step-wise GRPO 训练。**共同特征：学习对象是「何时取、取哪条、记不记」的效用/策略，作用的记忆载体是扁平的 episodic store。**

**诚实对比：三个他们比我们深的地方**

1. **效用闭环是定量的、逐条的、连续的**：每条记忆带一个从任务结果回传的效用值（Q(s,m)），自动影响后续召回排序。我们的 ⑤ 结果回写目前是规则式的（Daydream 反思），评测门是层级的、周期性的——**没有逐条记忆的效用学习**。这是真实差距。
2. **「记/忘/取」是学出来的策略，不是写死的规则**：能学到非直觉策略（例如何时*不*召回——他们宣称的 85.5% 触发一致率背后大概率是学/调出来的触发策略）。我们的召回时机是工程规则。
3. **跨场景泛化复用**：策略学一次、多场景迁移（宣称口径）。

**三个他们（公开材料中）没有我们深的地方**

1. **召回的结构**（我们最深的部分）：类型判断 → 解空间枚举 → 判别探测的三级漏斗，在其访谈与产品材料中**完全无对应物**。他们的框架回答「何时取、取哪条」（效用轴），不回答「按什么结构导航一个带类型的解空间」（结构轴）。**两个是不同的轴，不是同一轴上的深浅。**
2. **判别探测**（主动追问最小判别特征）：在全部已核实的记忆系统文献中均无对应，最近的亲缘在主动感知/二十问的信息增益文献——跨领域嫁接，目前是我们独有。
3. **记忆蒸馏为工程制品**（Task Pack / 技能 / AGENTS.md 片段）：其 Procedure Memory 神似但止于云端复用，无「蒸馏成制品」的表述。

**最高层的综合（路线关系的正确定位）**：漏斗与学习不是替代关系——**漏斗定义动作空间，效用学习定义策略**。没有类型层和决策点的扁平记忆库，学出来的策略只能是阈值策略（取几条、什么分取）；有了漏斗的结构化决策点，才有值得学策略的「动作」。Cyrus 的工程式漏斗恰好是任何学习路线（无论谁的）的必要脚手架——这是「工程先行」的理论正当性，也是 ADR-003 应写明的条款：漏斗每个决策点全留痕，日志即未来策略学习的训练集。

**对 Cyrus「噱头」判断的修正**：产品侧判断成立（MemoraX Code 产品内无 RL）；但「记忆=序列决策→RL」的理论框架本身成立，且已是学术浪潮（上述论文群均 2025-2026）。准确定性：**叙事先行于兑现的路线，不是噱头；但兑现依赖的脚手架，恰是我们在建的东西。**

### 9.8 「刚刚好」的形式化与漏斗细化路线（2026-08-20 Cyrus 补充拍板）

Cyrus 两点补充：① 漏斗三级只是目前已想到的部分，架构设计前需系统研究脑科学文献、把漏斗分得更细；② 召回的目标是「刚刚好」——召回率过高或过低都不行，**刚刚好能解决当前问题，就叫刚刚好**。

**「刚刚好」的形式化（Kimi）**：刚刚好 = 召回的**停止准则**问题——每多召回一条记忆的边际收益 < 其成本（上下文占用、干扰风险、token 消耗）时即停止。判据必须挂在**任务结果**上（「能解决当前问题」），而非挂在相似度分数上。这把评测指标从「召回率/准确率」升级为「任务解决所需的最小召回集」——与 MemoraX 宣称的 token −30% 同向，但我们的判据是任务结果，不是压缩率。

**漏斗细化用的文献锚点清单**（已核实 = 本轮联网核实；待核实 = 经典文献训练认知，设计阶段逐一复核）：

- 已核实六条：编码特异性（Tulving & Thomson 1973）、线索诊断性（Nairne 2002）、问题图式（Chi et al. 1981）、两段式粗筛精排（MAC/FAC，Forbus/Gentner 1994）、适应性遗忘与可及性开关（Richards & Frankland 2017；Ryan & Frankland 2022）、表面相似决定可检索性/结构相似决定有效性（Gentner et al. 1993）。
- 待核实五条：**知晓感**（feeling-of-knowing，Koriat）——对应 Cyrus 的「不需要精确记忆，只需知道有哪几种解法」；**信息觅食/边际价值停止**（Pirolli & Card）——「刚刚好」的判据来源；**合意困难**（Bjork）——检索练习本身强化记忆，解释 ⑤ 回写为何有效；**独特性编码**（Hunt & McDaniel）——判别探测的特征设计依据；**扩散激活**（Collins & Loftus 1975）——「灵光一闪」的联想路径。

**「他们比我们深的地方可以抄吗」（Cyrus 提问）的判断：可以，且应该——按三层分开抄**：

1. **非参数化效用学习（直接抄，成本低）**：MemRL 的 意图-经验-效用 三元组 + EMA 效用更新，本质是运行时算法，不需要训练任何模型，可在 V2 插件通道内实现。这是把 ⑤ 结果回写从规则式升级为定量式的最短路径。
2. **触发策略学习（抄思想，不抄设施）**：何时召回/何时不召回的策略，用我们评测门产出的标注数据做轻量化版本（阈值/策略表学习），不做参数化训练。
3. **记忆基模/参数化训练（不抄）**：训练设施与人才密度不对等，且与本地优先定位冲突——进「不做」清单。

两个不对称性提醒：① **我们抄他们便宜**（本地算法改动），**他们抄我们贵**（漏斗类型层要求云端记忆库改数据模型并迁移全部存量）；② 但「可以抄」是双向的——这正是 §9.4 保鲜三条件（评测实证 / 迭代速度 / 制品积累）必须执行到底的原因。

### 9.9 「RL 就是食溯问卷调权重」判断的核实（2026-08-20 Cyrus 类比，Kimi 拆解）

**Cyrus 的类比**：MemoraX 想训的不是一个模型而是一套权重；其逻辑与食溯问卷闭环同构——发问卷 → 用户答 → 问准不准 → 点「不太准」→ 调权重。RL 训练 = 一套收集用户反馈的数据结构 + 用数据调权重优化召回。

**Kimi 核实结论：类比基本成立，且比原话更准——但有两处被压缩**。

**成立的部分（比原话还准）**：MemRL 的非参数化版本（意图-经验-效用三元组 + EMA 更新）**字面就是**「每条记忆一个权重，按反馈调」——学术上这叫 contextual bandit（单步反馈→更新）而非深度 RL。食溯问卷闭环是一个已上线的生产级「反馈→权重」系统，Cyrus 等于已经做过一次这件事。所以轻量版效用学习对我们是已知模式，不是新能力——「直接抄」成立的根本原因在此。

**被压缩的两处**：

1. **反馈信号的质量差异（RL 线真正的成本中心）**：问卷反馈是**直接判断**（用户明说准/不准，信用分配天然完美）；记忆召回的反馈是**信用分配问题**——任务成功究竟是因为这条记忆还是绕过它？信号隐式、延迟、稀疏、有混杂。MemoraX 建 SWE-context-bench 等评测基准，本质就是**人工制造可靠奖励信号**。所以他们的壁垒不在「调权重」（谁都会），在奖励工程——这也是我们评测门 + 决策点留痕的战略价值：那是我们的奖励信号工厂。
2. **被调对象的规模**：食溯调的是几十维偏好向量（单机秒级）；「记忆基模」宣称调的是模型内部参数（若属实，需要梯度训练设施）。逻辑同构，优化机器的规模差几个数量级。**我们做 bandit 版（逐条记忆效用），不做基模版**——§9.8 三层抄法不变。

**推论：我们的「RL」落地形态 = 食溯问卷逻辑的记忆版**。反馈数据结构草案（P7 候选核心件）：每次召回事件记录 `{记忆ID, 任务类型, 召回时机, 显式反馈(有用/没用), 隐式反馈(是否进产出/任务是否解决), 时间戳}` → 每条记忆的效用分 = 反馈的指数滑动平均 → 参与召回排序。食溯经验可直接迁移：显式反馈稀但准、隐式反馈稠但噪，两者的权重配比食溯问卷已经趟过一遍。
