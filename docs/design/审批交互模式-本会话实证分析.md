## 3. 响应动作实证集（他真实用过的动作）

从 17 条消息提取，按出现频率排序：

1. **逐项混合裁决**（#5、#16）——一条消息内对不同项给不同判决，编号回复是他的稳定习惯
2. **批准 + 附加约束**（#12，#1 也算）——纯裸批准几乎不存在，「行，但按这个标准来」是主导模式
3. **打回重定向**（#14、#16）——拒绝我的提案并立刻给出替代任务；理由常是归属/时机/节奏，不是内容对错
4. **打回补料**（#16 Q3 要求具体示例、#9 要求论文、#3 查作业）——**抽象必被弹回，示例/证据才能过关**
5. **委托 + 半成型方向**（#16 Q4 日历：「我没想好，你多思考」；#6「你的理解呢」）——给方向不给方案
6. **假设验证请求**（#11「是不是这个逻辑」）——他出假设，我验证
7. **模式门控**（#1「不要写代码」、#15「先不动手」、#16「先思考」）——显式切换 动手/写文档/思考 三态
8. **仅要求理解**（#5⑤）——不要建议，只要听懂

## 4. 合作方式总结（权力分配）

- **他永远握有三权**：派发权（谁做，#14 把活派给 GPT）、排序权（何时做，「明天再做」「先思考」）、模式权（怎么做，动手/讨论/思考）。
- **我握有**：提案权（建议会被改写，但被期待提出）、举证义务（结论必须带证据/示例/路径）、规则内执行权（规则明确的事直接做，做了他不追）。
- **他的「同意」几乎都带约束** → UI 上「批准+补充约束」必须和「一键批准」一样便宜。
- **他要独立判断，不要附和** → 我验证后修正他的判断（如 MemoraX RL 定性为「叙事先行」而非纯噱头），他接受（#12「没问题」）。卡里应暴露 agent 置信度与异议，而非藏起。
- **存在一类「已决通报」事件**（#6）——他不是来问要不要做，而是告知已决 + 征求反对意见。这不是「待决卡」，是「压力测试卡」。

## 5. 对审批卡 schema 的设计修正（实证驱动）

1. 响应动作从 7 个修订为 **8 个**：批准 / **批准+约束**（新增，实证最高频）/ 打回补料（示例·证据·澄清）/ 驳回+方向 / 完全否决 / 委托 / 缓议 / 知悉（用于通报卡）。
2. 新增卡类型：**通报+压力测试卡**（已决事项，征求反驳，默认期限后自动生效）。
3. **质量门禁获得实证依据**：无具体示例/证据的卡历史上 100% 被弹回（#3/#9/#16Q3）→ 「信息不全不进队列」是正确的机器规则。
4. **批次必须支持混合裁决**（#5/#16 是常态）→ 逐项可分离是刚需，再次验证决策项原子化设计。
5. 每张卡标注**期望动作模式**（思考/讨论/文档/代码），因为他每次都显式门控，不该让他重复说。
6. **排序权机器不可越界**：队列只呈现，不自动置顶 agent 建议的下一步（实证：采纳率低）。
7. 规则应用类事项静默通过的事实 → 常备授权不是理论，是**已经在发生的现实**，控制台要做的只是把它显性化 + 留痕。
