## 0. 背景与结论先行

- 记忆系统 P0–P3 已上线（分片 SQLite + FTS5 关键词召回 + 自动候选提取）。当前召回弱点：**字面不匹配就漏**（记得「发布前先跑预检」，问「出包前的门禁」可能搜不到）。
- P4 = 语义召回升级：写入时给每条记忆算向量、查询时同样算向量，按语义相似度召回。
- **Cyrus 已拍板的决策**：
  1. 只用本地模型，不付费、不外发数据（否决远程 embedding API）；
  2. 不用 Ollama 独立进程（OpenClaw 时期手动伺候 Ollama + 断线卡顿的教训），要**零感知**：只开 DSH 一个东西；
  3. 因此形态定为：**内嵌 DSH 的 embedding 插件**，进程内加载 ONNX 权重直接出向量；
  4. 当前首选模型 **bge-m3**（本机已有 Ollama 格式副本，但本方案需要 ONNX 格式，需另下载）。

## 2. 目标架构（已定，评估通过后实施）

- 新插件 `@cyrus/dsh-embedding`（Host 侧，与记忆插件同级）：进程内加载 ONNX 权重，暴露评审定稿的合同（见下方接口），推理在**同进程 worker thread**（无端口、无外部服务、不堵 Host 主线程）。

```ts
embed({
  texts,
  purpose: 'query' | 'document',
  generation,
  signal,
}): Promise<{
  vectors: Float32Array,   // 扁平一维，避免 number[][] 复制开销
  count: number,
  dimensions: number,
  generation: string,
}>
```
- 运行时依赖：`@huggingface/transformers`（transformers.js，负责分词器/池化/加载的正确性）+ `onnxruntime-node`（原生模块，随桌面应用打包——与 SQLCipher 原生依赖是同一条已验证的打包路径）。
- 记忆插件经 DSH 内部 seam 调用（不建 HTTP 端口）。写入记忆时嵌一次、查询时嵌一次。
- 执行提供器：Windows 默认 CPU；DirectML 只在目标机器、目标文本长度与 batch 的 spike 证明更快时开启。本机 RTX 4090 上 DirectML 可用但显著慢于 CPU，不能按“有 GPU 就优先”选择。
- 生命周期：模型懒加载；推理放同一 DSH 进程内的 worker thread，不占端口、不启外部服务，同时避免阻塞 Harness Host 主线程。
- 选这条路的核心理由：embedding 质量**极其依赖分词器与池化方式与官方一致**（错了 = 静默产出垃圾向量且难察觉），transformers.js 帮我们把这部分做对；自己手写推理是造轮子且易踩坑。

## 3. 模型选型与评估

### 3.1 首选

**bge-m3**（BAAI）：MIT 许可；多语言（中文/英文均强）；1024 维；transformers.js 社区有现成 ONNX 量化版（Xenova/bge-m3）。2026-08-17 本地三模型 spike 后保留为正式推荐。

### 3.2 对比候选池（Codex 按 2026-08 实际状态核验后筛选）

| 候选 | 要点 | 注意事项 |
|---|---|---|
| Qwen3-Embedding-0.6B/4B | MTEB 强，多语言 | 体积/ONNX 可用性需核验；0.6B 优先 |
| multilingual-e5-large | 多语言稳定 | **需要 query:/passage: 指令前缀**，缺失会显著掉分 |
| gte-multilingual-base | 中文强 | ONNX 转换版需核验 |
| jina-embeddings-v3 | 多语言、任务适配 | 权重较大（570M），许可/转换需核验 |
| nomic-embed-text | 英文偏重 | 仅作「下限对照」，不指望它扛中文 |

### 3.3 评估标准（按权重排序）

1. **中文语义区分质量**（主场景 = 中文记忆；用统一测试句对打分，见 §5）；
2. ONNX 可用性（Xenova 社区转换版，或官方 onnx 权重 + 正确的 tokenizer/pooling）；
3. 体积（量化后 < 2GB，越小越好）；
4. 许可（MIT / Apache-2.0 优先，可本地商用/长期使用）；
5. 延迟（CPU 单句目标 < 100ms 量级；batch 16 可接受；DirectML 标注可用性）；
6. 社区活跃度与维护热度（2026-08 时点）。

### 3.4 已知陷阱（评估时必须核实并在报告中注明）

- pooling 方式（bge-m3 用 CLS 加权还是 mean？以官方 transformers 实现为准）；
- 指令前缀模型（e5 系）必须按 README 加前缀测试；
- 中文句子对测试必须包含：同义改写对、反义对、跨语言对（中文↔英文）、领域术语对（代码/发布流程类）。

## 5. Spike 验证（下载后执行，纯临时脚本，不写正式代码）

临时目录 `F:\AI\embedding-eval\spike\`，`npm init` + 安装 `@huggingface/transformers` 与 `onnxruntime-node`（以 transformers.js 官方文档当前稳定版为准），跑以下脚本：

```js
import { pipeline, cos_sim } from '@huggingface/transformers'
// 1) 加载本地 ONNX 权重（offline，不走网络）
const extractor = await pipeline('feature-extraction', 'F:/AI/bge-m3-onnx', { dtype: 'q8' })
// 2) 三组句对：同义 / 反义 / 跨语言
const pairs = [
  ['发布前必须先跑完整测试再出包', '每次出包之前都要把测试跑完', '同义'],
  ['发布前必须先跑完整测试再出包', '今天晚饭吃什么', '无关'],
  ['发布前必须先跑完整测试再出包', 'run all tests before packaging', '跨语言'],
]
// 3) 计时 + 余弦相似度
const started = Date.now()
for (const [a, b, label] of pairs) {
  const [va, vb] = await Promise.all([extractor(a, { pooling: 'cls' }), extractor(b, { pooling: 'cls' })])
  console.log(label, Number(cos_sim(va.data, vb.data).toFixed(4)))
}
console.log('elapsed ms:', Date.now() - started)
```

- ~~通过线：同义 > 0.8，无关 < 0.5，跨语言 > 0.7。~~ 2026-08-17 实测废弃：不同模型的 cosine 分布不可横比，且反义/否定句仍可能高相似。改用检索排名、相对 margin、hard-negative 错误类型与真实任务 helpful hit。
- 必测：CPU 单句/批量延迟；DirectML EP 可用性实测（可用/不可用都要写明）。

## 7. 评估通过后的正式开发（DSH 侧启动，不在本任务范围）

### 7.1 推荐开发顺序（三轮评审 §5.4 定稿）

1. 冻结 embedding 插件合同、generation 材料与模型 manifest 校验器；
2. worker-thread CPU-only 最小插件：只实现离线 health + query/document embedding（不接记忆写入）；
3. packaged Electron smoke：native 依赖随包、模型外置路径、退出与残留进程检查（dir/Portable/NSIS 三形态）；
4. 接入合成 memory fixture：异步 backfill、pending/ready/failed/stale 状态机、generation 回滚、坏模型/坏向量失败注入；
5. FTS/vector 候选并集 + RRF 名次融合，跑覆盖驱动的脱敏真实回归集；
6. **功能门通过后**才进 Dev 真人试用；Stable 仍需单独发布批准。

### 7.2 必须遵守的实现合同

1. `@cyrus/dsh-embedding` 插件（worker thread、懒加载、单飞初始化、队列上限、AbortSignal、关闭 drain/terminate）；
2. 记忆插件启用 `embeddings` 表（schema 已预留：provider_id/model_id/model_revision/dimensions/generation/status）；写入事务提交后异步嵌入，绝不把模型推理放进 SQLite 写事务；
3. generation 全合同锁定：model repo+revision、ONNX SHA-256、tokenizer SHA-256、dtype、pooling、L2 normalization、query instruction 版本、max length/截断策略、transformers.js/onnxruntime-node 版本；
4. 召回融合：scope/status/authority 硬过滤后，FTS top-k 与 vector top-k 候选**并集**，再 RRF/名次融合 + 精确 ID/路径/关键词加权 + 冲突/来源/新鲜度/预算门；不得只对 FTS 结果 rerank；
5. 运行时 `allowRemoteModels=false`：模型缺失/损坏 → `semantic_unavailable` 显式降级 FTS，禁止联网下载与远程回退；
6. **评测门**：FTS-only vs Hybrid 真实脱敏回归集（低字面重合/缩写别名/中英混合/否定反义/旧事实冲突/注入/跨项目同词异义/无需历史），helpful hit 提升达标、cross-project leak 仍为 0，才保留向量通道；否则自动降级纯 FTS。
