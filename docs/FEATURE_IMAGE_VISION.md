# 需求记录：识图功能（已确认 v0.2）

状态：**已实现 v0.2**（2026-08-15，P6→P8 之后随 14 号插件 @cyrus/dsh-image-vision 落地）。
记录时间：2026-08-15（v0.2 更新：Cyrus 逐项确认；同日完成实现）。

实现说明（v0.2）：聊天旁浮层入口（shell.overlay，与终端 dock 同模式）：选图（≤15 MiB 单张）→ 选择「连接中心」的模型连接（新增 kind `model`：OpenAI 兼容 API 地址 + 密钥，密钥只经 Host `credentials.resolve` 使用，UI 只显示「已配置」）→ Host 调 chat/completions（image_url data URL + 全能提示词）→ 结果卡（概括 / OCR / 界面分析，逐段复制，可回聊天继续追问）。费用暂不展示；保存到项目为后续能力（P7 项目页已就绪，待接）。

## 一句话需求

在 DeepSeek Harness Personal 桌面端里能够上传图片，调用**外部模型**进行识图（理解图片内容），并把识别结果以合适的方式呈现/使用。

## Cyrus 已确认的决定

1. **入口**：聊天里直接发图（在会话中上传图片，作为消息发给模型）。
2. **识别能力**：全能——OCR 文字提取 + 场景内容描述 + UI 截图分析，由模型自行判断。
3. **模型提供方**：多家可配置（类似 Connection Center 的管理方式，可切换使用哪家）。
4. **结果去向**：都要——先在聊天里回复（可复制、可继续追问），后续支持把识别结果手动保存到项目。
5. **隐私**：直接发送，不设每次确认（信任用户判断）。

## 待调研的技术问题（讨论用，不构成实现决定）

1. **rc.5 官方会话是否原生支持多模态图片消息**：
   - 若支持 → 聊天入口可尽量走官方消息链路（上传图片、消息里带图片、模型回复照常渲染）。
   - 若不支持 → 需要自建「上传 + 识图调用 + 结果以文本消息回填」的桥接（Host 侧调外部模型 API，结果以普通消息插入会话）。
   - 这决定实现路线，需要先做**只读调研**（阅读上游 rc.5 会话/消息类型与模型接口，不修改任何文件）。
2. **保存到项目**：依赖 P7 项目业务页；先只做「聊天回复」，保存到项目作为后续能力。
3. **一次多张**：待定（先支持单张，多张后置）。

## 技术备注（不变）

- 外部模型调用走 Host 侧有界适配（Renderer 不直接持 key），与 usage-balance/update-center 的 Host 边界一致。
- 图片是运行时用户数据，不得进入日志、项目库正文或发布物（发布红线见 docs/PUBLISHING_RULES.md）。
- 若引入新的第三方 SDK/依赖，先在临时 fixture 验证再进主线。
- 归属：独立新插件（暂定 @cyrus/dsh-image-vision），作为第 14 个插件接入。
