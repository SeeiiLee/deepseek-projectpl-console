## 0. 一句话总图（四件事的关系）

- **项目统合/迁移** = 物理归位：所有项目搬去 `F:\Projects\` 新根，各端重新绑定。
- **工具架构（D5）** = 内容物归位：skill/MCP/CLI/prompt 等工具跨端共用的目录、合同与流程。
- **架构族（D1/D4/ADR）** = 补给线：Harness/Personal/插件三条更新跑道 + 记忆跨端方案，决定迁移之后"东西怎么持续更新"。
- **治理闭环（D2/D3/说明书/B 线控制台）** = 操作系统：文档治理、审批管线、发布总账，决定这一切如何被管理、审批、留痕。
- 迁移是一次物理动作；它必须服从治理（审批卡/闸门），必须给工具架构让路（D5-2 在迁移后），必须避开补给线施工（A 线发布窗口）。

## 1. 项目统合与迁移（现状与结论）

权威盘点：`governance/项目路径绑定盘点表.md` v2（2026-08-21 全实测）。

**已拍板**：
1. 新根 `F:\Projects\`（独立于任何 Harness 数据目录，2026-08-21）。
2. 迁移顺序建议：Quant（最小，顺手去 ZWNJ）→ Amazon Store → meal_tracker → DSH Desktop（最大最后，先提交未提交文件）。
3. 软链过渡法：每个项目搬完在旧路径留 junction，各端分批改绑定，全部改完删 junction。
4. DSH 有原生换路径机制（project_path_history / rebind_proposals 表），迁移用官方机制，不手改数据库。

**实测关键坑（迁移手册必须逐一覆盖）**：
- 双库分叉：同一物理项目在开发库/稳定库有不同 `project_id`（已登记 identity_conflict，D5 不自行合并）。
- Quant 目录名含不可见字符 ZWNJ（U+200C）——迁移时用干净名，历史会话 cwd 走 C 线 alias 表。
- meal_tracker 与 OpenClaw 工作区根是父子关系——建议只搬子目录。
- Amazon Store 在开发库挂 tools 下、稳定库是独立项目——迁移时统一为独立项目。
- DSH Desktop 仓库含大量未提交文件，先提交再搬。

**待拍板**：
1. 五分类方案（platform/products/business/lab/archive；一个项目只属于一个类，拿不准放 lab，archive 只读）。
2. meal_tracker 与 OpenClaw 工作区根是否联动（建议：只搬子目录）。
3. 开发库 tools 项目下 Amazon source_root 迁移后是否清理。

**与 5 步迁移手册的对齐建议（供 Codex 整合参考，不另立标准）**：
Step 0 盘点冻结（已有盘点表）→ Step 1 新根与分类拍板 + 各端现状快照 → Step 2 逐项目迁移 + junction 过渡（每项目一张审批卡）→ Step 3 各端重绑定 + toolbox 落位 `F:\Projects\platform\toolbox\`（D5-0a 暂存物随迁）→ Step 4 验收（各端打开项目验证）+ junction 清理 + 治理闭环固化（注册表/盘点表/INDEX 更新）。

## 2. 工具架构（skill/MCP/CLI/prompts 跨端共用）

权威：`architecture/D5-统一工具层-跨Harness技能插件MCP-CLI共用架构.md` **v4.1**（三轮 Codex 审核已吸收；Project Control 薄接缝经 B 线 v4 复核沿用）。

核心机制清单（迁移手册涉及工具层时按此执行）：

1. **事实源模型**：资产事实源 = 工具自己仓库；期望状态 = toolbox.lock.json（生成）；实装状态 = 机器 receipt；运行数据（密钥/记忆/模型/缓存）全部外置专用数据根，不进 Git。
2. **toolbox 目录**：`F:\Projects\platform\toolbox\`（manifests/harnesses/adapters/profiles/schemas/scripts）；**当前暂存口径：开发版仓库 `toolbox/`，迁移时随 platform 分类搬走**（D5-0 闸门①已批）。
3. **三层清单 + 注册表**：manifest（声明，只引用 surfaces.v1 冻结 ID）/ lock（生成，头部带五方版本哈希）/ receipt（实装，带 operation_id/precondition_hash/rollback_coverage）。
4. **双层身份**：`harness_id`（产品家族，provenance 不可变）+ `harness_instance_id`（安装实例：stable/dev、local/WSL 各自独立）；apply/rollback/retire 全部对准实例。
5. **resolver**：七道硬门顺序冻结（身份→lifecycle→数据外传→权限/凭据/付费→协议代际→adapter→coverage），六态输出（exact/adapted/degraded/blocked/unconfigured/not_applicable），硬门未知 = blocked 不降级。
6. **项目缺省拒绝**：base profile 不授权项目访问；无 profile = unconfigured；身份冲突交回 Project Control；六态对账 = Project Control active inventory 总数。
7. **生命周期**：candidate→shadow→active→retiring→retired；retire receipt 三终态（clean/exceptions_approved/incomplete，远端未知 ≠ clean）；**卸载 Harness 默认不变更**（拆外壳不动核心）；re-onboard 沿用旧 harness_id + 重新 probe。
8. **快速配置管线**：`toolbox onboard/retire/reactivate/doctor` —— 一句话发起 + 一张审批卡决策 + 管线自动跑；机器可判定终态（产出包 ≠ 配置完成）。
9. **MCP 五问过滤 + 协议代际纪律**（modern/legacy 不互判 exact）；**skill 按目录包处理**；**ACP 子代理**（`kimi acp` 协议存在 verified，本机可用性 unverified）；prompt/AGENTS 治理按 `PROMPT_AND_AGENTS_GOVERNANCE.md`。
10. **与 Project Control 接缝（v4.1）**：PC 管任务/route policy/原子 claim；D5 只解析 capability/instance 并回 receipt；Harness 新增/替换/退役不改 WorkItem 或 workflow template。

**D5-0 执行状态（待核实）**：D5-0a 简报已盖章（2026-08-21，闸门①②③全批）并手工派发 Flash；**截至本包日期，开发版仓库内未见 `toolbox/` 产物**，执行状态需与 Flash/DeepSeek 侧核实。D5-0b（dsh 双实例盘点 + lock 漂移处置）挂 A 线收口后。

**分期硬约束**：D5-1（DSH Dev+Codex 两端闭环）在 A 线稳定后；**D5-2（记忆只读、项目绑定）必须在迁移完成后**——项目身份与物理路径先稳，绑定才不返工；D5-3 受控写 + 逐端扩。

## 4. 治理闭环

- **文档治理**：D3 十二目录骨架 + INDEX 唯一入口（双向一致）；被取代文档永不删除只留档；ADR 只追加。
- **LLM 治理说明书 v1.0**（`governance/LLM项目治理说明书.md`）：泛化到各项目；§10 五个机器可查不变量（INDEX 双向一致/位置正确/状态头/取代必有横幅/ADR 只追加）——**做成 preflight 门禁命令的任务已登记未排期，建议随治理闭环一并排**。
- **审批中枢（B 线 v4 已生效，2026-08-22）**：控制台 = 治理的机器执行面；单一 WorkItem 事实面；`effective_class=max(declared,required)` Host 兜底（Class A 永不合批、永不命中常备授权）；卡↔Decision 关联（保留否决历史）；列=分诊 / Workbench=裁决（approval-details viewer）。**B1 已具备派发条件，待 Cyrus 最终确认派发 Flash。**
- **迁移手册与审批管线的关系**：迁移的每个高危动作（改绑定/删 junction/清理 source_root/动稳定库）都应是一张审批卡；B1 落地前走手工派发 + 拍板清单模式（拍板项必须带人话解释，2026-08-21 立规 §21）。
- **发布治理**：PUBLISHING_RULES（红线门/模型哈希/商用剥离清单）、compat.json（机器基线）、发布总账（D2 §3.7）。
- **工作规则**：`WORKING_RULES_AND_PITFALLS.md`（含 §21 拍板请求纪律）；执行者名册与路由 `design/执行者模型与任务路由.md` v3（随 ADR-004 v4 生效）。
