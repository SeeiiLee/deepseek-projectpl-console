# ADR-002 记忆核心/外壳拆分（预登记）

- 状态：**预登记（草案）**——2026-08-20 登记，终审时间 = P5/P6 收尾期，终审人 Cyrus
- 关联：ADR-001（定位）；architecture/D4 §1（耦合面实测）、§6（路线）；architecture/D1 §9（V2 通道前提）

## 背景

记忆插件当前与 DSH 的耦合面很薄但真实存在：systemPrompt.section 注入、webServer 路由、credentials、tools、personal-shell UI 槽位，外加对 project-control / connection-center / skill-library 的插件间依赖。核心（SQLCipher 存储、bge-m3 嵌入、检索内核、提取 runtime、迁移链、评测 harness）宿主无关。跨端定位（ADR-001）要求核心可被多个外壳复用。

## 决策（拟）

1. 将 plugins/memory 拆分为**宿主无关核心** + **Host 适配层**（DSH seam 适配器为首个实现），定义显式的 Host 适配接口（端口）。
2. 拆分后首个新外壳 = MCP 服务器适配器（memory_recall / memory_store / memory_status）。
3. 拆分期间**冻结记忆系统其他架构大改**（不在移动靶上做手术）。

## 前提

- P5（智能层）/P6（稳定化）收尾完成，评测门全绿。
- D1 §9.3 的 V2 前提（依赖供给 + 迁移感知回滚）已就绪——拆分后核心与外壳仍走 V2 插件通道发布。

## 否决项

- **立即拆分**（2026-08 时点）：P5/P6 未完成，拆分目标在移动，否决。
- **不拆分、直接另写独立 MCP 服务器**：两套核心并存必然发散，否决。

## 影响

- 拆分 ADR 终审前，DeepSeek 在记忆插件上的新功能开发须保持「seam 调用与核心逻辑分层」的写法纪律（D2 seam 白名单的延伸），降低未来拆分成本。
- 拆分后插件间依赖（project-control 身份等）在其他端无等价物，各端适配器需提供降级方案（D4 §3）。
