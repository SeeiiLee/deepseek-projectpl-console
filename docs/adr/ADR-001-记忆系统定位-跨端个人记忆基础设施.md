# ADR-001 记忆系统定位：跨端个人记忆基础设施

- 状态：**生效**（2026-08-20 Cyrus 拍板）
- 关联：architecture/D4（§8 竞争格局、§9 漏斗理论）；architecture/D2 §3.6（本决策属 Class A 拍板样例）

## 背景

多端使用已成常态（Cyrus 同时使用 DSH / Codex / Zcode / Kimi Work / workbuddy）。各 Harness 厂商都在建自家记忆，但厂商记忆是**锁定手段**，跨端记忆层不符合任何厂商的商业利益——这个位置是结构性空位，只能由用户侧基础设施填补。AGENTS.md 是宣言式记忆（人写的静态宪法），时间拉长后承载不了经验式记忆（坑、决策、工作上下文）。

竞争格局（2026-08-20 核实，详见 D4 §8.2）：MemoraX Code 已四端在跑（Codex/Claude Code/DSH/OpenCode，MIT，云端记忆，数亿元融资）；Hindsight 需 PostgreSQL 守护进程；本地优先 + 加密 + 零运维的个人单用户位置空着。

## 决策

1. 记忆系统定位为**跨端个人记忆基础设施**，非 DSH 专属卖点。
2. 形态：核心/外壳分离——宿主无关核心（加密存储/嵌入/检索/提取/评测）+ 每端适配器。DSH 原生（T0）为首发端；MCP 适配器（T1）覆盖 Codex/Zcode/Kimi Work；提示词兜底（T2）覆盖无 MCP 宿主。
3. 单一数据根，全端共享一份加密记忆库；单写入者锁；来源端标记；模型资产共享。
4. 核心壁垒 = **召回管线的工程设计（漏斗式召回，见 ADR-003）**；本地加密零运维与个人纵深为定位楔形；插件深度集成为防御纵深。

## 否决项

- **「DSH 专属卖点」**（记忆插件商业化稿的论据）：否决。跨端定位包含单端卖点，反之不然；专属化锁死天花板，且跨端已是竞品在执行的方向，不跟进即出局。

## 影响

- D4 §6 路线激活，排序在 P5/P6 收尾之后。
- 核心/外壳拆分成为预定工作（ADR-002 预登记）。
- 商用剥离清单（PUBLISHING_RULES）按跨端形态重审许可。
- 各端召回质量分档：DSH 原生注入为上限；MCP 端召回靠工具调用，各端独立过评测门，R 层结论不外推。
