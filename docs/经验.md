## 一、红线（绝对不可违反，多数已有代码级强制）

1. **稳定版路径一律不碰**：
   - 安装目录 `D:\Cyrus Deepseek Harness`（含其中程序与插件）
   - 数据主目录 `F:\documents\Cyrus Deepseek Harness Data`（settings、project-control、harness-home、from-test-userdata 全在内）
   - 迁移前遗留备份：`%APPDATA%\DeepSeek Harness Personal`、`%APPDATA%\DeepSeek Harness Personal Dev`、`%USERPROFILE%\.dsh`
   - 自动化流程写入/删除前必须过 `scripts/protected-paths.js` 的 `assertAutomationSafe`（碰红线直接抛错）；测试版客户端由 Cyrus 亲自运行时对 `.dsh` 的 junction 重建属其自身设计行为，不算红线违规。
2. **进程清理只按 PID，绝不按名字**：`Stop-Process -Name` 曾误杀真实客户端（冒烟实例与真实客户端同名）。残留冒烟进程只准用 `node scripts/kill-smoke-orphans.js`（仅匹配 `-Smoke.exe` 名或命令行含 `dsh-desktop-smoke-`，且引用受保护路径的一律跳过）。
3. **冒烟必须完全隔离**：只启动 `*-Smoke.exe` 改名副本（`scripts/smoke-executable.js`）；temp userData / DSH_HOME / PROJECT_CONTROL_HOME。`DSH_DESKTOP_USER_DATA` 与显式 `DSH_HOME` 必须压过 flavor 覆盖——曾因这两处没生效，冒烟抢了真实客户端单实例锁、并把 F: 盘真实 harness-home 的插件 junction 指到临时目录。回归断言在 `test/app-flavor.test.js`、`test/protected-paths.test.js`。
4. **发布红线**：任何推送物不得含个人会话记录/数据/密钥；打包走 preflight-publish 扫描；功能完成并验证后才谈部署；GitHub Release 必须等 Cyrus 明确说「开始」。
5. **只读上游** `D:\Deepseek Harness`（rc.5）：调研可以，绝不修改。
6. **先临时 fixture，后主线**：新逻辑全部在临时目录/临时库里验证；不写真实项目目录；不安装稳定版（未获确认不 install/commit/push/publish）。
7. **一次只做用户点名的一件事**；重要确认用文字问，不要用选项卡片（选项答案曾传不回来）。

## 二、环境与工具链

- 无全局 pnpm：一律 `npx.cmd -y pnpm@11.19.0 run <script>`。常用脚本（仓库根）：`test`（全量 347+）、`build:plugins` / `check:plugins`、`pack:dev:portable`、`pack:win`、`smoke:packed:dir`、`smoke:packed:dir:dev`、`stage:releases`。
- 插件（15 个）在 `plugins/`；打包即 `check:plugins`；产物在 `artifacts/`（稳定）与 `artifacts-dev/`（测试）；交付暂存在 `分发包\测试版`、`分发包\稳定版`。
- **插件上架 = 四处都要改**：`plugins/<name>/`（package.json + tsconfig + tsdown.config）、`src/personal-plugins.js` 的 PERSONAL_PLUGINS、`plugins/cordis.patch.yml` 的激活清单、以及插件自己的测试。漏掉 cordis.patch.yml 的表现：冒烟 `missingEntries` 缺这个包（`passed:false`）。
- 类型检查：`& 'D:\Deepseek Harness\node_modules\.bin\tsc.cmd' -p <插件>\tsconfig.json --noEmit`，输出 0 行 = 通过。Host 代码需要 `"types": ["node", "react"]` + 两个 typeRoots（上游 @types + ui-theme）；用到 `shell.overlay`/`settings.section` 槽的插件，tsconfig references 必须包含 `packages/client/ui-layout`。
- tsdown 打包（`clientBundle` 预设）：**客户端 bundle 有纯度门禁，禁止跨插件 VALUE 导入**（type-only 导入会被擦除，可用环境声明 shim，如 project-control 的 `workbench-client.d.ts`）。Host 侧跨插件依赖运行时经 profile junctions 解析；为让 node 测试能加载模块，把这类依赖改成 **apply() 内的动态 import**（如 image-vision 对 personal-foundation store 的懒加载）。
- node:test：`.ts` 能跑（类型剥离），**`.tsx` 不能**——测试要 import 的纯逻辑（diff、outline、parse 等）放在独立 `.ts` 模块里。测试文件是 ESM：没有 `require`。
- 用 run_code 写文件：内容里含反引号 / `${` 会炸，一律用「字符串数组 join('\n')」拼接；edit 的 old_string 必须唯一。
- **PowerShell 沙箱**：命名管道受限——Node `child_process.spawn/exec` 用管道捕获输出会 EPERM，`stdio:'inherit'/'ignore'` 可用；别绕，改造结构。
- 冒烟失败排查：结果留在 `%TEMP%\dsh-desktop-smoke-*\result.json`（含 personalState 各字段），先读它再猜。**便携版 exe 的冒烟不可靠**（自解压壳与真实进程分离），一律冒烟 `win-unpacked` 目录版。

## 三、项目控制台（@cyrus/dsh-project-control）

### 数据库 / 迁移
- schemaVersion 已到 9，迁移 append-only + 校验和；**测试探针迁移要另起编号**（曾用 0009_probe 与真实 0009 冲突，改 0010_probe）。
- 0001 冻结了 `work_items`：execution_status ∈ draft/ready/running/paused/blocked/completed/cancelled；review_status ∈ not_requested/pending/changes_requested/approved/rejected；priority 整数 0–100；UNIQUE(project_id, work_item_id)。**不许改表，只能加新表或重建约束**（0009 用 `PRAGMA defer_foreign_keys` + rename-rebuild 放宽了 domain_events.aggregate_type）。

### 事件流铁律
- domain_events 只追加（update/delete 触发器拒绝）、`UNIQUE(aggregate_type, aggregate_id, aggregate_revision)`、`command_id UNIQUE` → **一条命令一个事件**；`aggregate_revision = before_revision + 1`。
- **事件 revision 必须与行 revision 同源**：外部更新用行 revision 作事件 revision；console 命令同样用行 revision（`recordConsoleEvent`），否则 UNIQUE 会撞车。createWorkItem/createRun 现在也发 `workitem.created`/`run.created` 事件（改断言时记得把事件计数一起改）。
- console 命令 = 行状态变更 + 事件（`console-event/v1alpha1`）+ CommandReceipt，**不发 outbox**（无渲染器/外部消费者）；评论只写 review_actions，不 bump 不 event。

### 审阅语义
- `request_changes` 把 review 关成 **rejected-with-feedback**（decided_by/decided_at 置位），work_item.review_status=changes_requested——这样修复后能开新一轮审阅，**绝不堆叠 open review**。approve→approved、reject→rejected。
- 请求审阅的前置：work_item.review_status ∈ {not_requested, changes_requested, rejected} 且无 open review。

### Outbox dispatcher（P6）
- 只处理外部事件（schemaVersion `normalized-event/v1alpha1`），渲染成 managed 项目的 `.dsh-project/updates/YYYY/MM/<stamp>-<updId>.md`；**legacy 项目不写文件只标记 delivered**（事实仍在 progress_updates/events 里）；生命周期事件保持 pending 留给未来消费者（过滤后再取 batch，避免饿死队列）。
- 失败退避（nextAttemptAt 指数）→ 达 maxAttempts 转 failed + 进 quarantine（先 transition 成功再 recordQuarantine，防止竞态误隔离）；drain 单飞（inFlight 共享）。

### 渲染器（updates-renderer）
- frontmatter 必须过冻结 schema：`aggregateRevision` 要输出为**数字**（yamlScalar 用 JSON.stringify，不能 String() 包一切）；空数组输出 `key: []` 流式写法；**evidence.title 必须丢弃**（envelope 允许、frontmatter schema 不允许）。正文五段顺序固定：`# summary` → 发生了什么 → 证据 → 下一步 → 阻塞与待决定，空段落写「无」。round-trip 测试复用 `src/discovery/runtime.js` 的 `parseYamlSubset`。

### HTTP 层（src/http.ts）
- `requireExactKeys` = 所有 key 都必填；可选字段用 `rejectUnknownKeys`。GET 路由要 `requireGetWithoutBody`；**POST 专用路由要按方法分流**，否则会挡住同名 GET 投影（`/projects/:id/work-items` 就踩过，GET 被 POST 路由 405）。
- 错误暴露：schema 违约→400 `SCHEMA_INVALID`；服务缺失→503 `EXTERNAL_UNAVAILABLE`/`CONSOLE_UNAVAILABLE`；StorageValidationError→500 `INTERNAL_ERROR`（保持私有）。
- 服务拆分：read / lifecycle / intake / external（P6 投影+握手）/ console（P7 指令），adapter 直连 storage；capabilities 列表随服务存在与否伸缩。

### 客户端（P7）
- `ProjectConsole.tsx` 七页 + `loadConsolePreferences`（pin/follow 存 localStorage）；命令都带 expectedRevision 乐观并发；typed open intent 走 `workbench.open({family, viewerId, resourceKey})`，**不重复实现查看器**（更新查看器 `project-control.progress-update` 独立注册）。

## 四、Workbench（@cyrus/dsh-workbench，P8）

- Host 远程 `/__personal/workspace`（单根 DSH_WORKSPACE_ROOT/cwd）：`resolveInside` 做 `realpath` 符号链接逃逸检查 + 前缀包含；读 ≤256KiB 文本/5MiB blob；**保存带 expectedSha256 乐观并发**，冲突回 409 FILE_CHANGED。

## 新坑（2026-08-15：发布与更新通道）

- **build-flavor 残留**：pack:dev:portable 中途失败会留下 src/build-flavor.js = 'dev'，全量测试 app-flavor「source tree defaults to stable」必挂；打包前/后先 Get-Content 确认已恢复 'stable'。
- **时点依赖测试**：project-control outbox 消息的 next_attempt_at 用的是真实时间戳，测试里 mock 时钟若硬编码固定时刻（如 13:00Z），过了该时刻消息永远「未到期」、测试必挂。mock 时钟必须锚定 new Date() 并动态推算期望值。
- **更新中心三条**：① 仓库必须公开（更新请求不带任何凭据）；② 设置里仓库必须填 owner/repo 格式，填完整 URL 会解析失败；③ 客户端版本与 Release 相同 = status current 不弹更新，必须发更高版本号才有提示。
- **GitHub Release 流程**（token 存 F:\QClawData\workspace\secure\github_token.txt，ACL 仅当前用户）：Draft 创建 → curl --data-binary 上传资产（大文件偶发 Connection reset，带 --retry 重试 3 次可过）→ API 校验资产清单 → PATCH draft:false。全程不回显 token；文档记录仓库/Release id/哈希，不记 token 值。
- 2026-08-15（治理线四项）：① run_code 写文件时内容里的反引号必须转义（fixture 脚本 SQL 模板字面量提前闭合了外层模板）。② 治理密扫不能把 token 片段存进仓库（会扫到自己）——改为从安全区读完整 token 做精确比对，命中 0 才过。③ pwsh 工具环境里 DSH_HOME 指向稳定版 harness-home，投影/守卫脚本的默认 home 必须显式传 dev home；守卫拒绝稳定版 home 是正确行为。④ SQLite 主键列隐式 NOT NULL：含 ON DELETE SET NULL 的列不得进 PRIMARY KEY，改用 UNIQUE。
- 2026-08-15（记忆 P1）：① FTS5 unicode61 不切中文——claims 加派生列 searchable_text（ASCII 词 + 中文二元组），写入时应用层分词，查询同变换；触发器只同步列值，派生必须应用层算。② 插件导入上游 VALUE 包（dsh-tools/schemastery）必须在 tsconfig references 里列上游工程（否则 TS6059 rootDir 雪崩）；先例 anysearch。③ cordis 插件配置走 export const Config = z.object(...) + apply(ctx, config) 第二参数；不存在 'config' 服务，inject 写它会导致「waiting for service: config」启动挂起。④ better-sqlite3-multiple-ciphers：key pragma 值必须单引号（连字符否则 near "-" 语法错）；VACUUM INTO 目标也要单引号。
- 2026-08-15（记忆 P2）：① 召回预算循环里把「字节+计数」混加会失效——累计预算必须单独用字节变量（byteLength+overhead）。② 上游 agent/pre-step 是现成的 request-scoped 注入 seam（plan-mode 先例）：handler 先 await next()，再把 UserMessage 追加进 decision.messages；不落历史。③ run_code 模板字面量里出现反引号（如代码片段）仍会提前闭合——文档正文里的内联代码一律去反引号。
- 2026-08-15（quick-pass 验证第 1 轮）：① 分发包里新旧版本并存 + 桌面图标指向旧 exe = 用户「升级了」其实还在跑旧包；诊断方法：新包 stage 时旧 exe EBUSY 即锁定实锤。② 旧包（无 System Policy）agent 会编造「已写 PROJECT_CONTEXT.md / 批准策略切换 never」——模型声明必须落盘核验，不可信其自述。③ 工具路由不能只靠工具描述：memory 插件要挂 systemPrompt 指引（order 150）+ AGENTS 路由规则双保险。
- 2026-08-15（加密引擎）：① koffi v3 API 与文档不一致（struct() 不返回构造器、pointer/as 签名变了）——DPAPI 暂缓，数据密钥暂以 hex 文件 + 用户目录 ACL 保护，写进合同「真实数据门槛前两步」。② 引擎抽象注意 prepare 返回类型：node:sqlite 的 prepare 可直接赋给窄接口，别再套 as unknown 双层强转（会把 as 绑到返回值上）。③ 加密备份：backup() 里 openShard 必须带 { encrypted } 选项，否则「file is not a database」。④ 测试里断言 throw 的引擎要 finally close，否则 Windows 下 rmSync EPERM。
- 2026-08-15（开发版直启）：.cmd 启动器必须纯 ASCII + CRLF（GBK 控制台会把 UTF-8 中文解析坏）；main.js 加 DSH_DESKTOP_FLAVOR 环境覆盖后，开发版直启与打包流程互不影响；直启前必须先 build:plugins，否则边改边跑会打崩客户端（历史教训）。
- 2026-08-15（工作台消失崩溃）：React 合成事件的 event.currentTarget 在重渲染后可为 null——所有插件 UI 的 value/checked 读取一律用 event.target；冒烟探针驱动 select 变更能稳定复现此类崩溃（先写复现探针再修，勿瞎猜）；面板级错误边界防整块消失。
