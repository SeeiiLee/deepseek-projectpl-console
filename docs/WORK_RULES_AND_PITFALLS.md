# 第一部分：系统层面原则（Agent 运行时纪律）

## 1. 证据门禁（Evidence-Gated）

- 只说被证据证实的话——测试输出、运行结果、文件路径。不说"应该可以了"。
- 依赖会随时间变化的信息（价格、文件存在性、任务状态）必须当轮用工具验证，不凭记忆断言。
- 不编造 API、库函数、数据、引用来源；查不到就承认。

## 2. 费用纪律

- 任何产生费用的操作（批量 LLM / 搜索 / 全管线跑报告）**先报价再执行**：预估费用 + 调用量级 + 失败重试策略，Cyrus 批准后才动手。
- 参考量级：全管线报告 KB 直供后 ~91-115s / 约 2 元；KB 建库单段目标 0.15 元；云南 11 段实耗 7.80 元（预算 9.21 内）。

## 3. 不可逆与对外操作

- 删除文件/目录、修改系统配置、`git push`、任何对外发送 → **必须先问 Cyrus**。
- 高风险写操作先 `--dry-run` 预览或列清单给用户确认。

## 4. 数据安全红线（PRD §4.2，不可妥协）

- **基因数据永不出本地、永不出用户库边界**：不进 API 请求、不进云备份、不进索引库。
- DB 存**相对路径**（相对用户目录 / 项目根）；代码中**永远不存绝对路径**。
- 索引库只存"找人在哪"（7 列），个人数据全在用户库。
- 密钥与密文物理分离：`.fernet_key` 在 `%USERPROFILE%\.nutrisight\`，密文在项目内；API key 统一走 keyring 读取。

## 5. 工作区纪律

- 工作目录：`F:\QClawData\workspace\meal_tracker`；生成物放工作区内。
- 临时脚本/验证脚本 → `data/tmp/`；报告产物 → `data/users/{user}/reports/{YYYY-MM-DD}/`。
- 不在仓库根目录新增散文件；不用 `test.py` / `tmp.json` / `debug.*` 无意义命名；debug 结束即清理临时 harness 与中间产物。
- 项目外的文件（如 DRI 扫描件）先复制进 `data/tmp/` 再处理，不直接动原件。

# 第二部分：项目层面原则

## 6. 关系定位与汇报纪律

- Cyrus = 领导者/PM/CEO，**不读不审代码**，基于结果判断。他要的是：打算做什么、为什么选 A 不选 B、结果是什么、和预期差多少。
- 每次交付四段式：① 做了什么（一句话）② 为什么这样做（一句 tradeoff）③ 结果（证据：输出/路径/测试数）④ 偏差（和预期的差异+原因）。用人话，不汇报代码细节。

## 7. 四大至高原则

1. **Leader's Intent**：行动前确认目标理解一致；偏离预期时诚实说明偏差与原因。
2. **Show, Don't Tell**：只说有证据的话。
3. **First Do No Harm**：不删/不改/不覆盖用户文件，除非明确要求。
4. **Expert Humility**：不知道就说不知道。

## 8. 编码哲学

- Think Before Coding：不确定就问；多方案并列附优缺点+风险，Cyrus 拍板。
- Simplicity First：能 50 行不用 200 行；不为一次性需求建抽象；不加没被要求的"灵活性"。
- Goal-Driven：先定义"怎么算做完"（可验证目标）再动手。
- Surgical Changes：只改必须改的；每行变更可追溯到需求；匹配现有代码风格。
- Boring Technology：稳定、广泛使用、文档完善。

## 9. 六条红线

1. 生产模式下不写测试 = 不完成
2. 不确定时先问，不猜
3. 不改没被要求改的代码；看到不该动的 → 记录 `NOTICED BUT NOT TOUCHING: ...`
4. 不加没被要求加的功能
5. 不删不理解的代码（Chesterton's Fence）
6. Bug 修复必须先写复现测试，再动手修

## 10. 六纪律触发路由

| 触发场景 | 纪律 | 核心规则 |
|---------|------|---------|
| 新功能 / 改已有行为 | TDD | 红→绿→重构；垂直切片（test1→impl1→test2→impl2），不批量；测行为不测实现 |
| 报错 / "不工作了" | Debug | 黄金法则：没有一条可复现命令，不进假设阶段；修复带回归测试 |
| 高风险（数据迁移/认证/不可逆/公共 API/批量费钱） | Doubt | fresh-context 子 Agent 对抗性审查；只传 artifact+contract；最多 3 轮后上报 Cyrus |
| 功能完成 / 合并前 | Review | 五轴：正确/可读/架构/安全/性能；Critical 必须处理 |
| 臃肿 / "太复杂了" | Simplify | 精确保持行为；清晰>聪明；>500 行用自动化工具 |
| 多文件 / >~100 行变更 | Incremental | 每切片一件事、可编译、测试绿、独立可回滚 |

本项目落地要求：TDD/Bug 修复 → 测试命令与结果写 DEVLOG；高风险变更（管线架构/双库 schema/数据迁移）默认走 Doubt。

## 11. 确认与自主边界

- **必须先问**：未给"开始"信号前不写新功能代码；费钱操作先报价；删除；改系统配置；`git push` 及对外操作；装系统级软件。
- **可自主**：读文件/搜索/查文档；工作区内写改文件；跑测试；本地 `git commit`（message 写清做什么+为什么）；装项目依赖。
- **卡住时**：同一问题修 3 次未好 → 停止死磕，列已试方案与当前假设，给下一步建议。

## 12. 文档纪律

- **PRD 是唯一真相来源**；架构改动先对齐 PRD，落地后回写 PRD。
- 每个有实质产出的 Session 写 `docs/DEVLOG.md`（Session N + 小节 + 结果 + 下一步；修复类用四段式：发现什么/怎么修/为什么/修后状态）。
- 跨 Session 交接写 `docs/HANDOVER_*.md`；任务队列变化同步 `docs/NEXT.md`。

## 13. 技术栈锚点（改动前先对齐）

- 统一包：`from src.xxx` 绝对导入，**禁止新增 sys.path hack**。
- 双库：索引库 `data/nutrisight.db` + 用户库 `data/users/{display_id}_{name}/user.db`；KB 库 `data/kb/nutrisight_kb.db`（FTS5）。
- 存储层：`src/data/user_store.py` / `cache_store.py` / `kb_store.py` / `dish_store.py`——**不绕过存储层直写 SQL**。
- 管线 M1-M10 模块化，上游产物经 manifest 传递；非致命模块失败记 placeholder 不炸报告（FATAL_MODULES 白名单）。
- LLM = DeepSeek（**必须 `thinking: disabled`**）；搜索 = AnySearch；USDA 食物数据 = FoodData Central。
- Git：垂直切片 commit；push 前必问；主分支 master；首次 push 前需 orphan 分支 squash 重建历史（旧 commit 含已清除敏感文件）。

## B. 静默失败类（本项目最大反复出现的敌人——教训：显式失败优于静默降级）

15. **CSV GBK 编码**：`parse_tencent.py` 硬编码 utf-8-sig → GBK 问卷静默解析失败 → 支持 gbk + 编码检测。
16. **TRPV1 75 分硬编码**：旧 JSON 解析失败 → 手动填假分 → 报告用假数据。教训：解析失败必须报错，禁止兜底假数据。
17. **M2 用户画像静默丢失**：`ctx.upstream("_input", "ok")` 误把模块状态当 step 名，`get_artifact` 静默返 `{}` → age/gender/waist 永远空串。修法：改对 step 名 + **manifest 最小契约校验**（挂账：模块入口声明 requires，runner 统一检查，静默衰减变显式失败）。
18. **性别默认值静默错误**：无法识别时默认女 → 改显式报错，让 runner FATAL 路径拦截。
19. **PAL 断链**（Session 48，Cyrus 亲抓）：新链路 import_user 从未灌 04d/04e → `exercise_freq=None` → PAL 静默兜底 1.3，高强度运动反被判久坐。修法：04d 存全文 + import 灌字段 + M4 默认值透明化；**默认值兜底必须在报告里可见**。
20. **m4_targets 静默断言失效**：`ctx.get("_full_micros", {})` 双参数 vs `ModuleContext.get()` 单参数 → TypeError 被吞成 warning，断言从未执行。修法：`(ctx.get("_full_micros") or {})` + 排查同类调用。
21. **keyring 静默生成新钥**：丢钥时静默生成新钥 → 新钥解不开旧密文，所有 API key 永久锁死且无报错（数据毁灭型故障）。修法：密文存在时丢钥即显式报错。
22. **runner 零容错**：单模块失败炸整个报告 → `run_modules()` 失败记 fail + placeholder，finalize 无条件执行，partial 报告入库。
23. **recipe_cache 写而不读**：缓存只写不读白烧搜索费 → KB 切换后由 kb_cache 直供。
24. **genetics.js 404**：引用 `/core/genetics.js` 但静态根只暴露 `app/web/` → 线上静默损坏（首页有 typeof 兜底未炸，体测页必抛错）。教训：有兜底的地方故障不可见，要主动巡检。

## C. LLM 工程类

25. **DeepSeek JSON mode 15-key 上限**（坑 #15）：超 15 key 直接拒绝 → 顶层压到 3 key（facts/narrative/sources），facts 用 list 不用 dict 绕开嵌套 key 上限。
26. **JSON 截断**：max_tokens 不足 → JSON 截断解析失败（白烧 ≈1.7 元）→ max_tokens 8000 + parse_json_loose salvage + 重试。
27. **req_timeout 不随 max_tokens 伸缩**：大输出超时 → req_timeout 随 max_tokens 动态伸缩。
28. **"夜间降级"假象**（Session 39）：实为推理模型思考烧光输出预算 → **`thinking: disabled`**，单段 ~2 分钟。这是 LLM 调用最重要的单点教训。
29. **分块合并 source_ids 张冠李戴**：多块提取合并时来源编号错位 → 证据链机器强制（无源条目自动降级 gaps）+ source_ids 越界检测。
30. **LLM 数字主权**：LLM 不可信复述数字 → 五闸体系（在池/数字主权/时间锚定/长度/菜-营养关联）+ 拒收喂回重试恰好 1 次 + 按段模板降级（降级粒度=单段不整卡）。数字由脚本格式化，LLM 不碰数字。
31. **闸①遮蔽法漏洞**："鸡蛋"标配词吞掉池菜、allowed 子串遮蔽未授权菜 → 重写**区间覆盖法**；中文数词（十一次/两三次）绕过数字闸 → 统一转换函数封死（百千 fail-closed）。
32. **why 字段类型陪葬整卡**：why 值 None/list/dict → repr 化混过五闸 → `text.strip()` 裸炸 → isinstance 守卫。教训：**可选字段的坏值不能陪葬整卡**。
33. **max_tokens 膨胀截断**：A5 输出膨胀 → 2500→4000。

## D. 标签与词表类

34. **鸡蛋≠鸡误判**：词表裸匹配 → **屏蔽表（MASK_WORDS）机制**根治（鸡精/鸡豆/鱼香/牛肝菌/牛奶/猪油等 15+ 词）；教训：加词前先想"这个词会误伤什么"。
35. **鱼通道未接屏蔽**：只加 MASK_WORDS 而鱼不在 `_MASKED_CATS` → 加词无效。教训：机制接线完整性要验证，不能只改数据。
36. **民族前缀裂行**：汽锅鸡"苗家/苗族"裂 3 行 → 别名归一 + dedupe_generic_ethnic；建库流程挂账"菜名归一查重"。
37. **数据抽象度不足**："多种肉类/酱料等"配料太抽象，规则与 LLM 都判不准 → 补数据比裁标签更有价值。
38. **虫宴无桶可放**：9 品类体系无"其他动物"归属 → Cyrus 拍板第 7 轴"昆虫"（归荤、不占红白肉、不作常规推荐）。教训：词表扩充前先拍板体系归属。
39. **打标工具 v1 致命 bug**：`getElementById("c-"+CSS.escape(k))` 找不到元素（getElementById 不做 CSS 转义解码）→ 首卡即抛异常脚本全死。修法：元素直接引用 + addEventListener 全量，杜绝字符串拼接转义；**node 冒烟测试实跑**后才交付。

## E. 数据与流程类

40. **密钥密文同仓**：`.fernet_key` 与 `api_keys.enc.json` 同目录且同被 git 追踪 = 明文 → 密钥外迁 `%USERPROFILE%\.nutrisight\`；双副本（app/config 与 src/config）收敛。
41. **旧 commit 含敏感文件**：`git rm --cached` 只清索引不清历史 → 首次 push 前必须 orphan 分支 squash 重建历史。
42. **import_user 重复导入**：users.display_id 无 UNIQUE 约束 → 重复执行插重复行 → 修法已定（加 UNIQUE + 导入前查重显式报错）。
43. **重试双层叠加**：单 step 最多 9 次调用（费钱放大器）→ 重试收敛为恰好 1 次 + 降级路径。
44. **UTC 翻日 bug**：本地日期用了 UTC → `localYMD()`。
45. **USDA 营养素 ID 错误**：维D 1114(µg)→1110(IU)、维K 1183(MK-4)→1185(K1) → 数值全错。教训：外部数据源的 ID/单位要逐个核对官方文档。
46. **CFCT 数据被 USDA profile 覆盖**：11 个回归食物修复 → 数据源优先级明确。
47. **时间锚定漏词**："N 月"豁免不容许空格，prompt 实际写"8 月"带空格 → `\s*月`。教训：校验正则要与 prompt 实际输出对拍，不能凭想象写。

## F. 方法论沉淀（从坑里提炼的元规则）

1. **静默失败是最贵的 bug 类**——默认值、兜底、except 吞异常、缓存写而不读，全是"看起来在跑其实在骗"。每个兜底都要问自己：故障时它可见吗？
2. **假数据比缺数据恶劣十倍**——宁可空态诚实（"库中仅 1 道虾候选"），不可编造填满。
3. **LLM 输出必须过闸**——数字主权、在池校验、来源证据链，机器强制优于 prompt 请求。
4. **词表/规则改动先想误伤**——每个新词配屏蔽词审查；机制接线完整性单独验证。
5. **Doubt 对抗性审查物超所值**——M7 全程 5 轮 Doubt 抓出 6🔴20+🟡，全部是实证真问题（骨架贪心假性不可行、遮蔽法双洞、数字闸三洞等）。
6. **真机验收不可替代**——E5/A4/A5 三次真机各抓出单测抓不到的真 bug（字符串形态崩溃、问卷盲区、闸碰撞消失等）。
7. **修复先写复现测试**——红灯精准命中再动手，修完测试留作回归（本项目回归套件 0→472 全绿就是这样攒出来的）。
