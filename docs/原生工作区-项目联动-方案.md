## 1. 现状机制（已核实）

- 右侧工作台文件树绑定只有一个入口：项目控制台项目卡片「打开控制台」→ Host API workspaceStatus → workbench.setProjectWorkspace(projectId, root)；onBack → clearProjectWorkspace() 回到会话工作区。
- 原生侧栏的 workspace/session 浏览区由上游 ui-workspace 拥有（sidebar.workspaces 槽），其服务 ctx.workspaces.list 是 store（items 含 workspaceId/path/title）；点击会话条目走 ctx.sessions.open。
- 项目根目录权威来源：Project Control（F:\QClawData\workspace\meal_tracker 已注册为食溯；亚马逊、量化盯盘 Cyrus 已关联注册）。

## 2. 联动规则（v1）

1. **触发**：当前会话的工作区（原生侧栏中打开的会话所属 workspace）变化时联动；点击侧栏工作区条目即触发其下会话打开，进而工作区变化。
2. **匹配**：会话工作区 path 与 Project Control 项目根归一化（大小写不敏感、去尾斜杠）后精确匹配；多项目根重叠时最长前缀优先。
3. **行为**：匹配到项目 → workbench.setProjectWorkspace(projectId, root)（右侧文件树切到该项目）；匹配不到 → clearProjectWorkspace()（回会话工作区）。
4. **双向同步（v1 简化）**：项目控制台「打开控制台」继续可用，保持现有行为；原生侧栏点击同样生效。两者都只写同一份绑定状态，后者覆盖前者。不做「原生侧栏高亮」反向同步（留 v2，若需要）。
5. **零风险**：全部只读 Host API + 客户端 store 订阅；不写数据库；项目未登记/无权限时静默回退会话工作区。

## 3. 实施位置与步骤

1. personal-shell 客户端新增 effect：订阅上游 workspaces.list + 当前会话绑定，取「当前会话 workspace.path」。
2. 拉取 Project Control 项目根列表（复用现有 Host API /projects 或 project-control 客户端的 workspaceStatus）。
3. 路径匹配（归一化 + 最长前缀），调用 workbench.setProjectWorkspace / clearProjectWorkspace。
4. 边界：会话切换、项目控制台 onBack、控制台「打开控制台」三者状态统一由「最后一次操作」决定（v1 不建仲裁，行为可预期）。
