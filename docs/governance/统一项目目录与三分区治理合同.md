# 统一项目目录与三分区治理合同

> 版本：v1.0
> 状态：权威
> 生效依据：ADR-009（Cyrus，2026-08-25）
> 适用范围：`F:\Projects\` 下的所有受管项目，以及 Project Control、跨 Harness Skill/记忆、工作树、生成物和迁移流程
> 当前实施状态：合同已冻结；2026-08-25 已为 DeepSeek Harness Personal 手工建立首个 `bootstrapping` Project Home 与 canonical 候选，但 Project Control 三分区产品实现、binding 晋升、跨 Harness 和其他项目迁移尚未完成

## 0. 结论速查

一个项目只有一个稳定 `project_id`，但拥有三个物理分区：

```text
F:\Projects\<project-slug>\
├─ .project-home\
│  └─ project-home.json     # Host 管理的 locator/zone 合同，不是第二身份源
├─ workspace\              # canonical 项目根：源码、docs、AGENTS、manifest
├─ worktrees\              # 开发 checkout；每个工作树必须登记来源和状态
└─ local\                  # 本机生成物/运行时/receipt；不进 Git/发布/默认记忆扫描
```

`workspace` 是 Project Control 的 primary workspace；Project Home 是机器上的管理容器；路径变化不改变 `project_id`。

## 1. 术语与身份

| 名称 | 含义 | 是否身份源 |
|---|---|---|
| Project Home | `F:\Projects\<slug>`，三个分区的共同容器 | 否，只是 locator |
| Workspace | `Project Home\workspace`，canonical 项目根 | 否，路径可迁移 |
| Worktree | `Project Home\worktrees\<worktree-id>` | 否，必须绑定同一 project_id |
| Local | `Project Home\local`，机器生成物和运行数据 | 否 |
| Project ID | `prj_<uuidv7>`，Project Control 颁发并在 managed manifest 中持久化 | 是 |
| Harness Instance | 某 Harness 的某安装/profile 实例 | 否，只是来源与访问主体 |

身份规则：

1. 同一项目在 DSH Stable、DSH Dev、Codex、Kimi、Zcode 等端必须使用同一 `project_id`。
2. 绝对路径、slug、文件夹名、Git remote、仓库 URL、本机用户和 Harness 名称只能帮助发现，不能创建/替代 `project_id`。
3. managed 项目的 `workspace\.dsh-project\project.yaml` 保存同一 ID；各端 Project Control/adapter 只做事务镜像与 binding。
4. legacy 项目发生双 ID 冲突时，迁移前必须人工选择 canonical ID，旧 ID 写 alias/superseded receipt；禁止静默选择、合并或新造第三个 ID。
5. 推荐顺序：已有真实 Stable 生产绑定时优先保留 Stable ID；若已有 managed manifest，则 manifest ID 优先。任何例外由 Cyrus 逐项目确认。

## 2. 物理总根

### 2.1 固定总根

```text
F:\Projects\
```

`F:\Projects\` 独立于 Harness 安装目录、Harness userData、Stable 数据根和任何单一宿主的配置目录。

### 2.2 项目 Home 命名

- Home 直接位于 `F:\Projects\<project-slug>`；默认不增加 platform/products/business/archive 物理分类层。
- slug 使用稳定 ASCII kebab-case；创建后不因产品分类、阶段或状态变化而改名。
- 项目性质、标签、生命周期、归档、负责人和排序全部进入 Project Control 元数据，由 Console 分组显示。
- 重名时停止并要求用户选择；不得自动加随机后缀后声称同一项目。

首批目标示例仅作迁移定位，不代表已创建：

```text
F:\Projects\deepseek-harness-personal\
F:\Projects\meal-tracker\
F:\Projects\amazon-store\
F:\Projects\cyrus-quant-trading\
F:\Projects\toolbox\
F:\Projects\memory-system\
```

## 3. 三分区合同

### 3.1 workspace

`workspace\` 是唯一 canonical 项目根，应包含：

- 项目源码、业务资料或研究资产；
- 项目根 `AGENTS.md`；
- `.dsh-project/project.yaml`；
- README、PRD、架构和 D3 文档骨架；
- Git 工作目录（适用时）；
- 可版本化的 schema、policy、脚本和小型 receipt 摘要。

禁止长期放入：

- node_modules 的复制备份；
- E2E 完整 run；
- 安装器集合和 unpacked App；
- 真实用户数据；
- 可重建 cache；
- Harness profile、DSH_HOME、模型权重和跨端记忆库；
- 其他工作树。

### 3.2 worktrees

推荐结构：

```text
worktrees\
├─ active\<worktree-id>\
└─ receipts\               # 小型本机登记；权威状态仍由治理 ledger 持有
```

每个工作树至少登记：

- project_id；
- worktree_id / role / owner / task_id；
- base_commit / expected_parent / current_head / tree_hash；
- created_at / last_used_at；
- lifecycle：ACTIVE / QUARANTINED / RETIRED / DELETABLE / PINNED；
- dirty/untracked 清单 hash；
- rollback_ref；
- cleanup eligibility 与阻断原因。

规则：

1. 工作树只能来自 canonical workspace 的 Git common repository 或可证明的镜像；无共同历史时必须显式记录 transplant，不冒充 merge。
2. 新任务开工 preflight 必须验证 HEAD 是获批父基线的后代；否则在任何写入前失败。
3. 旧工作树只有在唯一改动全部迁移、hash 对齐、组合测试通过、成果持久化、rollback 有效后才能进入 DELETABLE。
4. 工作树不按“七天没用”自动删除；源码 checkout 的清理由生命周期决定，不由普通 artifact retention 决定。

### 3.3 local

推荐结构：

```text
local\
├─ artifacts\
├─ runs\
├─ runtime\
├─ cache\
├─ quarantine\
├─ receipts\
├─ ledgers\
└─ snapshots\              # 同盘快照不是备份；真实备份必须另有介质/根
```

规则：

1. local 默认不进 Git、不进发布包、不作为 Project Intake 的项目候选、不进入记忆正文扫描。
2. local 内任何大对象创建前必须注册 manifest：owner、run/task、project_id、kind、created_at、expected_bytes、retention_class、source hashes。
3. cache/runtime 可重建不代表可任意删；必须由 owner 与 lock/进程状态证明不在使用。
4. quarantine 只接收治理系统能够归属但不能自动处置的对象；未知来源保持只读并生成阻断，不静默吞掉。
5. Stable 数据、真实用户数据、凭据和 F 盘现有受保护根不因进入本合同而自动迁入 local。

## 4. Project Home marker

未来 Host 创建：

```text
.project-home\project-home.json
```

最小语义：

```json
{
  "schemaVersion": "project-home/v1",
  "projectId": "prj_<uuidv7>",
  "slug": "example-project",
  "zones": {
    "workspace": "workspace",
    "worktrees": "worktrees",
    "local": "local"
  },
  "createdAt": "UTC timestamp"
}
```

约束：

- 文件由 Host 生成并校验，不接收任意绝对路径；zones 只能是本 Home 下的固定相对路径。
- 它引用 Project Control 的 `project_id`，不颁发身份；与 workspace manifest 不一致时 fail closed。
- marker schema、Host validator、fixture 和 crash/retry 合同未落地前，Console 不得声称支持三分区新建。

## 5. 新项目治理骨架

Project Console 创建新项目时必须分两层落盘。

### 5.1 Project Home 层

```text
.project-home/project-home.json
workspace/
worktrees/
local/
```

### 5.2 workspace 层

至少包含：

```text
AGENTS.md
README.md
.dsh-project/project.yaml
docs/INDEX.md
docs/adr/
docs/governance/
docs/prd/
docs/architecture/
docs/design/
docs/reviews/
docs/handoff/
docs/verification/
docs/release/
docs/logs/
docs/attachments/
docs/archive/
```

每个模板必须同时提供：

- 项目 AGENTS 速查与按需路由；
- 权威/草案/留档状态规则；
- PROGRESS/NEXT/BLOCKED 入口或等价机器投影；
- protected paths 和授权边界；
- 测试/构建/发布命令占位；
- artifact/retention policy 的项目默认值；
- 不把待填写模板文字伪装成已确认事实。

已发布的模板版本不可原地修改；三分区属于新模板/新协议能力，必须新增版本并显示升级 diff。

## 6. Global AGENTS、项目 AGENTS、Skill 与记忆

### 6.1 Global AGENTS

- 只保存跨项目、跨 Harness 的稳定工作原则和“何时读取什么”的路由。
- 规范源最终应从单一 DSH 仓库迁到受管的跨端治理/Toolbox 规范源；各 Harness 用适配器投影并记录 hash receipt。
- 每个 Harness/profile 的投影目标彼此隔离；共享规范源不等于共享可写 DSH_HOME。
- Project AGENTS 只保存项目专属增量，不复制 Global 全文。

### 6.2 可复用 Skill

toolbox 本身也是标准项目：

```text
F:\Projects\toolbox\
├─ workspace\              # manifest、schema、adapter、规范源
├─ worktrees\
└─ local\                  # instance inventory、probe、receipt、locks
```

投影生命周期：doctor → plan/diff → approval → apply → receipt → rollback/retire。

Skill 以完整目录包管理；新增 Harness 通过 descriptor/adapter 接入，不能要求修改每个 Skill manifest，也不能从另一个宿主副本反向复制。

### 6.3 统一记忆

memory-system 也是标准项目：

```text
F:\Projects\memory-system\
├─ workspace\              # memory core、MCP/adapter、schema、评测
├─ worktrees\
└─ local\                  # 加密 DB、models、writer lock、receipts、backups locator
```

访问纪律：

1. 一个 memory-host 负责单写入者；各 Harness 走 MCP/原生 adapter，不直接并发打开库。
2. 读写必须带 project_id；身份不明只允许 status。
3. provenance 保存 harness_id、harness_instance_id、project_id、时间与证据来源。
4. 各 Harness 独立跑召回质量和泄漏评测；DSH 通过不能外推 Codex/Kimi/Zcode。
5. 原始个人数据、凭据和未授权内容不能因“统一记忆”自动跨项目或跨端流动。

## 7. 生成物生命周期和清理

### 7.1 状态

| 状态 | 含义 | 可自动删除 |
|---|---|---|
| ACTIVE | 被当前任务/进程使用 | 否 |
| QUARANTINED | 等待迁移核对、故障分析或人工裁决 | 否 |
| RETIRED | 不再使用，但关闭证据未齐 | 否 |
| DELETABLE | 关闭条件与 retention 同时满足 | 可按获批 policy |
| PINNED | 明确保留的证据/回退资产 | 否 |

### 7.2 默认 retention 语义

“最近 N 次或 T 天”统一解释为：**对象既不在最近 N 次内，并且年龄超过 T，才可进入 DELETABLE**。

建议初始默认值，必须在真实体积测量后由 Cyrus 固化：

- 成功 E2E：保留最近 2 次，并保留 7 天内全部；
- 失败 E2E：保留最近 3 次，并至少保留到 issue 关闭或 14 天；
- 中断且无有效证据：72 小时；
- PINNED：无自动期限；
- 工作树：不用此时间策略，只走 §3.2 生命周期。

### 7.3 执行闭环

```text
discover/register
  → cleanup-plan（只读，列出保留/删除理由与预计字节）
  → policy/approval check
  → cleanup-apply（只执行带 hash 的计划）
  → verify（目标消失、保护对象仍在、空间复算）
  → append-only cleanup receipt
```

每日调度、登录补跑和大型任务前预检共同执行。机器关机时不承诺墙钟准点，但下一次登录/开工必须补跑；逾期、磁盘不足或删除失败时停止新的大型 run。

### 7.4 删除安全边界

- 只允许登记过且带 project marker 的 local 根；
- 解析真实绝对路径并验证 containment；
- 拒绝根目录、workspace、worktrees、受保护根、junction/symlink/reparse point 越界；
- 未知对象只报告，不纳入自动删除；
- 清理计划、实际删除与复验都有 receipt；
- Windows 计划任务的创建属于系统配置，首次启用需 Cyrus 明确授权。

## 8. 存量项目迁移事务

每个项目独立执行：

1. 只读盘点当前根、Git/common-dir、project_id、Harness binding、历史 cwd、快捷方式、进程、dirty/untracked、artifact 与受保护数据；
2. 生成逐文件/逐对象 hash manifest，确认 canonical project_id 和源码基线；
3. 在目标 Home 创建一次性 staging，不覆盖已存在目录；
4. workspace 只迁移项目资产；worktrees 重新创建或精确迁移唯一改动；local 只迁移经分类的运行资产，不复制 cache/node_modules；
5. 运行项目测试、路径门禁、Project Control identity/binding、Skill/记忆 scope 和 artifact 扫描；
6. 原子晋升新 workspace，更新各 Harness binding；历史 cwd 使用有期限 alias/junction 过渡；
7. 观察期内旧根标 QUARANTINED，只读保留；
8. 所有端完成 rebind、无唯一文件、rollback 有效后，旧根标 RETIRED/DELETABLE；
9. 经批准执行 cleanup-plan/apply/verify/receipt；
10. junction/alias 清零后才算迁移完成。

禁止：整盘批量移动、跨 shell 拼删除命令、复制 node_modules、让旧路径持续承接新 run、未验证就删旧根、把同盘快照称为备份。

## 10. 新建项目机器验收

Console 只有满足以下条件才可显示“创建完成”：

- Home、workspace、worktrees、local 与 marker 原子落位；
- project-home 与 workspace manifest project_id 一致；
- workspace 模板通过 schema/hash，AGENTS 与 docs/INDEX 在位；
- worktrees/local 被源码扫描、Git、发布和记忆正文扫描明确排除；
- primary workspace binding 指向 `workspace`；
- 同 slug、非空目标、越界、reparse point、磁盘不足、崩溃重放均有反例；
- 文件提交后再提交 Project Control 事务；W1-W4 恢复不留孤儿 Project/Home；
- 创建 receipt 包含 template、policy、path plan 与输出 hashes；
- 未完成以上任一项只能显示 rejected/quarantined，不能显示成功。
