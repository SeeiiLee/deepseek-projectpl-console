## 四、迁移预备结论（2026-08-25 以 ADR-009 为准）

1. **新根已拍板（2026-08-21）**：`F:\Projects\`（独立于任何 Harness 数据目录）
2. **Project Home 三分区已拍板（2026-08-25）**：物理第一层直接使用稳定项目 slug；项目分类和生命周期全部进入 Project Control 元数据，不再使用 `platform/products/business/lab/archive` 物理分类层。

```
F:\Projects\
├── deepseek-harness-personal\
│   ├── workspace\
│   ├── worktrees\
│   └── local\
├── meal-tracker\{workspace,worktrees,local}\
├── amazon-store\{workspace,worktrees,local}\
├── cyrus-quant-trading\{workspace,worktrees,local}\
├── toolbox\{workspace,worktrees,local}\
└── memory-system\{workspace,worktrees,local}\
```

- `workspace` 是 canonical 项目根；`worktrees` 放开发 checkout；`local` 放运行时/构建/E2E/cache/receipt。详细合同见 `docs/governance/统一项目目录与三分区治理合同.md`。
- D3 十二目录只落在每个项目的 `workspace/docs`，与外层三分区互不替代。

3. **G4 迁移顺序（Cyrus 2026-08-25 最终拍板）**：Amazon Store 主要是 skills 与调研报告，先迁（→ `amazon-store\workspace`）→ Quant 只有一套初版架构，第二个迁并去除 ZWNJ（→ `cyrus-quant-trading\workspace`）→ meal_tracker/食溯是复杂项目，最后迁（→ `meal-tracker\workspace`）。DSH Desktop 的文件基线已先完成 canonical 收敛，不混入这三个项目的 G4；其真实 binding/双 ID 另案处理。
4. **软链过渡**：每个项目通过迁移 plan 后，旧路径可在获批观察期内 junction 到新 `workspace`；各端分批改 binding，全部改完且 retire receipt 通过后再删 junction。Project Home 根本身不作为旧项目 cwd 的替代目标。
